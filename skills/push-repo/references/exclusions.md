# 排除清單規格（`_repo_excluded.tsv`）

這份檔案是 push-repo 的核心。`.gitignore` 是給 git 看的規則，`_repo_excluded.tsv` 是給人看的帳本：**clone 之後看不到的東西，只有在這裡留得下名字**。

## 檔案格式

第一列必須是表頭，四欄，以 tab 分隔，UTF-8、LF：

```
path	size	reason	backup
```

| 欄位 | 型別 | 說明 |
| --- | --- | --- |
| `path` | 相對路徑 | 相對 repo 根目錄，用 `/` 分隔，不加 `./` |
| `size` | 位元組整數 | 目錄則為其內所有檔案總和 |
| `reason` | 一句話 | 為什麼沒進去（見下方詞彙表） |
| `backup` | 一句話 | 原件的**唯一副本**在哪；空白 = 未交代，驗證 FAIL |

## `path` 的三種寫法

| 寫法 | 意義 | 例 |
| --- | --- | --- |
| `a/b.txt` | 單一檔案 | `assets/big_video.mp4` |
| `a/b/` | 整個目錄（尾端 `/`） | `dist/`、`legacy/` |
| 含 `*` `?` `[` | glob，**能不用就不用** | `logs/*.log` |

目錄寫法要小心：`legacy/` 會連帶涵蓋 `legacy/` 底下全部檔案。若只想排除巢狀 repo 的 `.git` 而保留內容，那不是排除，是「攤平」——見 `troubleshooting.md`。

## `reason` 詞彙表

固定用這幾類開頭，方便日後 grep 與統計：

| 前綴 | 用於 |
| --- | --- |
| `機密：` | `.env`、token、私鑰，附上偵測到的樣式 |
| `雜物：` | `__pycache__`、`node_modules`、`.DS_Store`、`*.log` |
| `產物：` | `dist/`、`build/`、編譯輸出 |
| `大檔 N MB：` | ≥50 MB 的檔案，附上在哪個門檻（50 警告／100 硬擋） |
| `巢狀 repo：` | 子目錄自帶 `.git` |
| `既有 .gitignore：` | 沿用對方規則而沒進去，但需要人確認 |

## `backup` 詞彙表

不要寫「無」或「N/A」——那等於沒回答。可接受的值：

| 值 | 意義 |
| --- | --- |
| `由工具重建` | 可執行檔、快取、建置產物；刪了可再生 |
| `雲端：<位置>` | 「Google Drive/備份/2026-11」，要能被人找到 |
| `本機唯一，勿刪` | 世界上只有這一份，刪掉就沒了 |
| `已上傳 <URL>` | 有明確可回溯的位置 |
| `移至 <路徑>` | 被搬出 repo 但還在磁碟上 |

## 對帳等式

```
磁碟上的檔案 = 已追蹤檔案 ∪ 排除清單涵蓋的檔案
```

沒有第三類。`verify_push.py` 會逐一列出落在第三類的路徑並 FAIL。常見的第三類來源：

- 先 commit 了，之後才改 `.gitignore` → 仍在索引裡
- 用 `.gitignore` 的 pattern 排除，但沒寫進清單（**RED 基線最常見的失敗**）
- 巢狀 repo 被記成 gitlink（`git ls-files -s | grep 160000`）

## 錯誤示範

```
assets/*.mp4	57671680	大檔	由工具重建
```

三個問題：用 glob 而非實際檔名（未來新素材會靜默消失）、`backup` 說謊（素材不能重建）、沒寫是哪個門檻。

## 正確示範

```
assets/big_video.mp4	57671680	大檔 55.0 MB：≥50 MB push 會警告	本機唯一，勿刪
dist/	12582912	產物：建置輸出	由工具重建
.env	68	機密：含 sk- 樣式	本機唯一，勿刪
legacy/	19	巢狀 repo：已改為攤平見 commit 2	不適用（內容已進 repo）
```

最後一列是「決定不排除」的紀錄：如果你曾考慮排除、後來放進去了，用 `不適用` 說明，不要留空白。
