# 子主題 02：平台演進與工具鏈

> 本地來源：`docs/{legacy_inventory,system_inventory,decision_nodes}.md`、`physics_lab/`、`多模擬/`、`多模擬II/`、`physimOld/`、`掃瞄/`、`README.md`
> 蒸餾日期：2026-11-12

## 1. 一句話定位

「物理模擬」repo 內含四代平台（physics_lab → 多模擬 → 多模擬II → physim）加上一個非物理的軟體分析工具鏈（CodeInsight，`掃瞄/`）。physim 是最終形態，前三代保留原位作為 legacy 資產；遷移採分批、高/中/低可移植性分級。

## 2. 四代演進對照表

| 世代 | 目錄 | 核心引擎 | domain 數 | UI | API | 狀態 |
|------|------|----------|-----------|----|-----|------|
| 1 | `physics_lab/` | numpy/scipy + matplotlib（grill 技） | 3 個 simulations（acoustics/celestial/classical） | Streamlit pages | 無獨立 API | 原型 |
| 2 | `多模擬/` | SymPy Lagrangian/Hamiltonian + ODE solver | 4（classical/celestial/chaos/chaos_control） | Streamlit | FastAPI（可選） | Phase 1 |
| 3 | `多模擬II/` | SymPy + ODE/PDE + phase space（Lyapunov/Poincaré） | 11（classical/celestial/chaos/chaos_control/acoustics/thermodynamics/optics/electromagnetism + …） | Streamlit 儀表板 | FastAPI 閘道（11 領域 endpoint） | Phase 1–3 |
| 4 | `physim/` | core 契約 + lru_cache numerics + registry | 22（見 09 §5） | Streamlit + panel | service/contracts + CLI | 主線（backbone） |

來源：各代 `README.md`、`docs/legacy_inventory.md` §1–2。

## 3. 各代設計取捨

- **physics_lab**：早期原型，Bottom-Up 架構：`core/`（BaseEntity/BaseEngine/BaseRenderer、integrators：euler/verlet/rk4/adaptive_rk45、particles/nbody/rigidbody/wave）、`simulations/`（classical/celestial/acoustics + registry）、`visualization/`（plotly_2d/pyvista_3d/streamlit_ui）、`pages/`（app.py）、`decorators/`、`utils/`；含 `physics_lab.zip` 與 `grill技.md`（4 行）、`qpkg.md`（1 行）。
- **多模擬**：引入 SymPy Lagrangian/Hamiltonian 解析、MathLive LaTeX↔SymPy 橋接、統一 ODE/PDE 求解器、相空間分析；Phase 2/3 為規劃中。
- **多模擬II**：擴充到 11 領域，加入 Shannon 資訊（thermodynamics）、OGY 渾沌控制、聲學/光學/電磁；FastAPI 閘道；授權條款。
- **physim**：最終形態，三層分離、registry、preset、深連結、lru_cache、測試矩陣；不 import 舊檔。

遷移理由（`docs/legacy_inventory.md`）：physim 以 numpy/scipy/matplotlib 為基底，避免 SymPy/Streamlit/panel/pyvista 混入 core；舊模擬保留原位。

## 5. 工具鏈：CodeInsight（`掃瞄/`）

注意：這是**非物理**的軟體專案分析平台，與物理模擬無關，僅同 repo。

- 產品名：CodeInsight — 軟體專案分析與總覽平台。
- 規模：12 個 Streamlit 頁面、4 個 FastAPI 路由模組（認證/專案/分析/編輯）、分析引擎（tree-sitter + jedi）、資料庫 Schema（12 張表）、API 客戶端。
- 技術：FastAPI + Streamlit + PostgreSQL + tree-sitter + jedi。
- 定位：同 repo 的工具鏈，非物理主題；蒸餾時應分離，避免混入物理 topic。

來源：`掃瞄/README.md`、`掃瞄/檔案功能.md`、`掃瞄/檔案結構.md`。

## 6. 遷移路線圖

來源：`docs/legacy_inventory.md` §4–5、`docs/decision_nodes.md`。

- **B1 高優先（可直接數值化）**：基礎力學、混沌、波動/統計/天體。
- **B2 中優先（需重寫互動）**：穩定性/線性化、剛體 2D。

決策節點（待確認）：`docs/decision_nodes.md` §C 列出文件缺口（usage/testing）與新系統候選；建議順序 A3。
